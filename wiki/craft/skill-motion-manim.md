# Скиллы: принципы моушна, Manim, ИИ-клип по картинке

Разбор трёх репозиториев из [[anim-skills-catalog]] под стиль из [[style-bible]]: 3D-окружение и
плоские 2D-человечки, всё кодом, 720×1280, 30 fps. Как они ложатся в общий конвейер, см.
[[reproduction-pipeline]]. Тест Manim проведён 2026-11-14 на этой машине (Windows 11, Python 3.11,
Manim Community 0.22.1, без LaTeX).

## 1. Принципы моушна (`LottieFiles/motion-design-skill`)

### Установка и запуск
- `npx skills add LottieFiles/motion-design-skill`, у нас уже стоит как скилл `motion-design`.
- Зависимостей нет. Это 17 markdown-файлов (~58 КБ), рендера и кода нет. MIT.
- Структура: `SKILL.md` (короткий справочник) + `director/` (8 файлов: философия, 12 принципов
  Диснея, эмоции, хореография, нарратив, личность движения) + `reference/` (таблицы тайминга и
  easing, выбор свойств, чек-лист, «болячки») + `patterns/` (входы и выходы, фидбек, эмбиент, группы).

### Как пользоваться
Скилл срабатывает сам на словах «анимация», «переход», «easing». Для нас полезнее явно сказать:
«по motion-design подбери тайминг и easing для …» и дать персональность **Playful** (для
иллюстраций это значение по умолчанию). Перед анимацией скилл гоняет чек-лист из 8 шагов: эмоция →
персональность → главное свойство → длительность → easing → герой → вторичные слои → правила 1/3.

### Что даёт нашему стилю
Скилл написан для UI (кнопки, модалки, карточки), но в нём есть конкретные числа, которые
переносятся на актёрскую игру человечков, камеру и титры:

| Правило из скилла | Где взять | Как применяем у нас |
|---|---|---|
| Squash `[1.2, 0.8]`, stretch `[0.85, 1.15]`, удар 2–4 кадра, восстановление 4–8 кадров, объём сохраняется | `director/disney-principles.md` | Смех-подпрыгивание, приземление после прыжка, удар |
| Упреждение: 100–200 мс, 10–20 % от основного действия, в противоположную сторону | `disney-principles.md`, `narrative-structure.md` | Присед перед прыжком, отклонение головы перед поворотом |
| Follow-through: дочерний элемент отстаёт на 50–150 мс, хвосты останавливаются на 100–200 мс позже | `disney-principles.md` | Шляпа, усы, руки-«макаронины» догоняют голову и тело |
| Вторичное действие: амплитуда 30–50 % от основного, старт через 50–100 мс, другой easing | `core-philosophy.md` | Брови и усы двигаются с ртом, тень от прыжка |
| Три слоя движения: основной 100 %, вторичный 30–50 %, эмбиент 10–20 % | `core-philosophy.md` | Персонаж + аксессуары/камера + пыль/свет ламп |
| Не больше 1/3 экрана без промежуточного ключа; не больше 1/3 элементов в движении одновременно; один «герой» на бит | `choreography.md` | Бег на камеру ломаем на ключи; в кадре с двумя героями двигается один |
| Никогда linear для перемещений (только вращение и прогресс) | `SKILL.md`, quality-checklist | Камера и персонажи только с easing |
| Вход = ease-out, выход = ease-in (65–75 % от длительности входа), на экране = ease-in-out, петли = sine | `timing-easing-tables.md` | Выход персонажа из-за края кадра, уход из кадра |
| Playful: 150/250/400 мс, ease-out-back, overshoot 10–20 %, траектории — дуги; больше 25 % overshoot = «сломано» | `motion-personality.md`, troubleshooting | Сигнатурный easing канала для мимики и жестов |
| Energetic: 100/180/300 мс, ease-out-expo, overshoot 15–30 % | `motion-personality.md` | Только для ударов, взрывов, «удара» камерой |
| Встряска: 2–3 колебания с затуханием, ±10–15 px, 300–400 мс, без overshoot | `patterns/state-feedback.md` | Встряска камеры при выстреле или взрыве |
| Пыль и «мушки»: 5–10 частиц, 10–30 px/с, 2–5 px, прозрачность 20–50 % | `patterns/ambient-continuous.md` | Пыль в лучах ламп |
| Параллакс: передний план 1.0×, средний 0.5×, фон 0.2× | `ambient-continuous.md`, `choreography.md` | 2.5D-сдвиг слоёв, если 3D-камера дорога |
| Дыхание в простое: масштаб 0.98–1.02, sine, 2–4 с на цикл | `ambient-continuous.md` | «Живой» персонаж, когда не говорит |
| Структура: подготовка 20–30 % → действие 30–40 % → развязка 30–40 %; 100–200 мс тишины перед следующим движением | `narrative-structure.md` | Каждый жест и каждая реплика |
| Arcs: смещение 10–20 px перпендикулярно пути в середине (Playful — 20+ px) | `disney-principles.md` | Взмах руки, жест «указать», полёт предметов |

**Оценка: 3/5.** Сам ничего не рисует, а числа рассчитаны на UI в миллисекундах и местами
противоречат ритму Shorts: «бюджет стаггера < 500 мс», «мобильный ×0.8», «избегать
вестибулярных триггеров — зума и быстрых смен направления» к нам не относятся, у нас
push-in и whip идут по сюжету. Полезен как словарь Диснея в числах и как чек-лист «почему
выглядит дёшево» (нет вторичного слоя, линейный easing, нет follow-through).

### Ограничения
- Нет ни строки про камеру в видео (push-in, dolly, whip), липсинк, монтаж и титры. Всё ниже в
  шпаргалке по этим пунктам выведено по аналогии и сверено с [[style-bible]].
- Easing задан в CSS-нотации (`cubic-bezier`), в Manim, Three.js или GSAP его надо переводить
  (для Manim таблица соответствий ниже).

### Вердикт
**Брать как источник правил тайминга, не как инструмент.** Таблица ниже — выжимка из него.
Вызывать при постановке мимики и жестов персонажа и при ревью «почему кадр мёртвый».

## 2. Математическая анимация (`adithya-s-k/manim_skill`)

### Установка и запуск
- `npx skills add adithya-s-k/manim_skill` ставит 3 скилла: `manim-composer`,
  `manimce-best-practices`, `manimgl-best-practices` (у нас уже стоят).
- Движок: `pip install manim` (у нас 0.22.1). ffmpeg нужен (есть). LaTeX нужен только для
  `MathTex`/`Tex`, без него работает `Text` (Pango).
- Рендер вертикали: `python -m manim -r 720,1280 --fps 30 --disable_caching file.py Scene`, плюс
  в коде `config.frame_width = 8 * 720/1280`, иначе вертикальный кадр растянется.
- Лицензия MIT. Примеры ManimGL взяты у 3Blue1Brown, на них CC BY-NC-SA.

### Как пользоваться (что внутри)
- **`manim-composer`** — планировщик: ресёрч → вопросы → `scenes.md` по сценам (длительность,
  объекты, камера, нарратив). Ритм «быстро-быстро-МЕДЛЕННО», камера 2–3 с, пауза 0.5–1 с. Заточен под
  ролики 5–30 минут в стиле 3Blue1Brown.
- **`manimce-best-practices`** — 22 файла `rules/` (сцены, анимации, Transform, текст, LaTeX, цвета,
  оси, 3D, тайминг, апдейтеры, камера, CLI, config), 3 шаблона (`basic_scene`, `camera_scene`,
  `threed_scene`), примеры (3D-поверхности, Лоренц, attention).
  - Камера 2D: `MovingCameraScene` + `self.camera.frame.animate.scale().move_to()`, `save_state`/`Restore`, `auto_zoom`.
  - Камера 3D: `ThreeDScene.set_camera_orientation(phi, theta, gamma, zoom, frame_center)`,
    `move_camera(...)`, `begin_ambient_camera_rotation`, `add_fixed_in_frame_mobjects` (титры поверх 3D).
  - 3D-примитивы: `Prism`, `Cube`, `Cylinder`, `Cone`, `Sphere`, `Surface`, `Line3D`; `set_shade_in_3d`.
  - Тайминг: `run_time`, `rate_func` (`smooth`, `there_and_back`, `ease_out_back`, `ease_out_bounce`…), `lag_ratio`.
- **`manimgl-best-practices`** — то же для версии 3Blue1Brown (OpenGL, интерактивный `-se`,
  `frame.reorient`). У нас не установлен движок `manimgl`, не тестировали.

### Что даёт нашему стилю
- **2D-человечки — да, хорошо.** Круг с толстым контуром, точки-глаза, рот из трёх форм с
  подменой, руки-дуги (`ArcBetweenPoints`, «rubber hose»), squash через `stretch_to_fit_*`,
  апдейтер по `ValueTracker` даёт покадровый контроль. Линия ровная, «не кипит», как в эталоне.
- **3D-окружение — нет.** Cairo-рендер рисует 3D как плоские полигоны по алгоритму художника:
  нет источников света с затуханием, теней, тумана, объёмных лучей, DOF, текстур, z-буфера.
  Перспектива и `move_camera` (push-in, dolly, поворот) работают.
- **Титры — да.** `Text(font="Montserrat", weight=BOLD)` + `set_stroke(BLACK, background=True)`,
  позиция y≈900/1280, жёсткая подмена слова.

**Оценка: 2/5 для стиля целиком** (5/5 для инфографики и плоских вставок, 1/5 для 3D-мира).

### Результат теста
Код и рендеры: `C:\dev\tools\anim-tests\motion-manim\`
- `scenes.py` — 3 сцены; `media/videos/scenes/1280p30/*.mp4`; контактные листы `sheets/*_sheet.png`
  (ffmpeg `fps=3,scale=240:-1,tile=6x2`).

| Сцена | Что внутри | Длительность | Время рендера (с запуском Python) |
|---|---|---|---|
| `MineBeams3D` | `ThreeDScene`: 7 рам-балок из `Prism`, рельсы, лампы-сферы, слово «salting» через `add_fixed_in_frame_mobjects`; push-in (`zoom` 0.9→1.5 + `frame_center` вперёд, 1.5 с), трекинг-поворот 0.6 с, встряска 8 кадров | 3.77 с (113 кадров) | **15.3 с** (~4× реального времени) |
| `StickLaugh` | `MovingCameraScene`: голова-круг (stroke 8), глаза, 3 рта (дуга, «O», смех с языком) с подменой каждые 3 кадра, смех-подпрыгивание 10 кадров на цикл со squash 12 %, push-in 0.85, подмена титра «ha!» → «salting» | 4.0 с (120 кадров) | **3.7 с** (~1× реального времени) |
| `BillboardIn3D` | Человечек-плоскость (повёрнут в x-z) стоит в 3D-туннеле, push-in 2 с | 2.5 с (75 кадров) | **11.2 с** |
| `MineBeams3D` через `--renderer=opengl` | та же сцена | 3.77 с | 6.1 с, **но картинка сломана** |

**Как выглядит против эталона:**
- Персонаж: силуэт и мимика попадают в «палочника» (круглая белая голова, тёмно-коричневый контур,
  смена ртов, подпрыгивание читается). Не хватает тела-«капли» с одеждой, градиент-тени на голове,
  бровей, аксессуара. Всё это рисуется теми же примитивами.
- 3D: перспективный туннель из балок и перспективный push-in работают, но это «плоская заливка без
  света»: стойки сливаются в стену, нет тёплого света ламп, лучей, пыли, DOF. До «Pixar-шахты»
  далеко, и средствами Cairo-рендера это не исправить.
- Билборд: человечек в 3D масштабируется по перспективе корректно, **но рельсы рисуются поверх
  его ног**. Cairo сортирует объекты по центру, а не попиксельно, поэтому длинные объекты
  перекрывают персонажа. Для сцен «бег по шахте» это фатально.

### Ограничения и проблемы (в т. ч. Windows)
1. **`ease_in_out_cubic`, `ease_out_back` и др. не экспортируются через `from manim import *`** в
   0.22.1 (`NameError`), хотя `rules/timing.md` использует их напрямую. Надо писать
   `rate_functions.ease_out_back`. Скилл здесь ошибается.
2. **Флага `--write_to_movie` нет** в 0.22.1. OpenGL-рендер (`--renderer=opengl --format=mp4`) в 2.5
   раза быстрее, но с `ThreeDScene` даёт неправильный ракурс и горизонтально сжатый текст.
   Экспериментальный, для продакшна не годится.
3. В `MovingCameraScene` зум камеры масштабирует **и титр**: слово растёт вместе с push-in. Титры
   надо держать в отдельном слое (собирать ffmpeg-оверлеем или компенсировать масштаб).
4. Вертикаль требует ручной `config.frame_width`. Пресеты `-ql/-qm/-qh` горизонтальные.
5. Скорость 3D на Cairo ~7 кадров/с на простой сцене. 60-секундный ролик с насыщенным 3D — десятки
   минут на рендер, с ростом геометрии хуже.
6. `manim` в PATH есть (`Python311\Scripts`). Предупреждений в логах не было, шрифт Montserrat
   из `C:\Windows\Fonts` подхватился без настройки.
7. Скиллы ориентированы на обучающие ролики 5–30 минут: темп «пауза для осмысления 0.5–1 с»,
   камера 2–3 с. Для Shorts с 53 сменами в минуту композер надо переписывать.

### Вердикт
**Не основа стека.** Manim не тянет 3D-окружение из [[style-bible]] (свет, объём, пыль, DOF,
правильное перекрытие). Плоского персонажа он рисует хорошо, но тот же «палочник» проще и быстрее
делается на 2D-canvas/SVG рядом с three.js, где есть билборды с z-буфером (см. [[reproduction-pipeline]]).
Оставить Manim для **вставок-инфографики** (цифры, схемы, «10 FT ↑»), если они понадобятся.

## 3. ИИ-клип по картинке (`LunaAI519/motion-skill`, команда `/motion`)

### Установка и запуск
- `git clone https://github.com/LunaAI519/motion-skill ~/.claude/skills/motion` (у нас стоит как `motion`).
- Требует 2 MCP: **nanobanana** (Gemini, свой API-ключ) и **higgsfield** (кредиты). MIT.

### Как пользоваться (точный разбор `SKILL.md`, он на китайском)
- Триггеры: `/motion`, «动画» (анимация), «把图动起来» (оживи картинку), «图生视频» (видео из картинки).
- Вход: путь к референс-картинке + описание движения («медленный наезд, ветер в волосах»), формат
  (по умолчанию 9:16), длительность. Без картинки первый кадр генерируется из текста.
- Стиль по умолчанию — **ретро-коллаж из бумаги**: насыщенный однотонный фон с фактурой бумаги
  (кирпичный, кобальт, тёмно-зелёный), герой — чёрно-белая полутоновая вырезка из старого фото с
  белой обводкой-наклейкой и тенью, рваная бумажная плашка с жирным словом, немного геометрии.
  «Сдержанное движение: элементы наклеиваются по очереди, лёгкое stop-motion дрожание, **камера
  полностью неподвижна**».
- Шаги: (1) `mcp__nanobanana__gemini_generate_image` делает ключевой кадр, показать пользователю;
  (2) загрузить кадр в Higgsfield (`media_upload`); (3) `mcp__higgsfield__generate_video`, модель
  `kling3_0_turbo` (≈7.5 кредита), `seedance_2_0` дороже в 3 раза и требует тариф Pro, сначала
  `get_cost: true`; (4) по желанию `upscale_video`.
- Правила: не генерировать реальных людей, логотипы, чужих персонажей; музыка только без
  авторских прав; одно видео за раз; каждое списание кредитов подтверждается.

### Что даёт нашему стилю
**Подтверждено: это ИИ-генерация (Gemini-картинка → Kling/Seedance image-to-video), а не код.**
Ни строки рендер-кода, только промпт-шаблоны и вызовы MCP. Стиль (бумажный коллаж, статичная
камера) противоположен нашему (3D-мир, движущаяся камера). В [[style-bible]] зафиксировано, что
ИИ-видео не используется. **Оценка: 0/5.**

### Результат теста
Не запускали: по ТЗ стек — код, а генерация требует ключа Gemini и кредитов Higgsfield
(MCP Higgsfield в этой сессии не авторизован).

### Ограничения
Платно за каждый клип, нет контроля покадрового тайминга, нет повторяемости персонажа между
шотами, нельзя синхронизировать с речью и титрами.

### Вердикт
**Не берём.** Единственное, что можно взять, — идея «показать ключевой кадр и подтвердить до
дорогого шага» как правило конвейера.

## Шпаргалка тайминга для нашего стиля

Источник правил — motion-design (персональность **Playful** как основная, **Energetic** для ударов),
числа переведены в кадры при 30 fps (1 кадр = 33 мс) и сверены с замерами [[style-bible]]
(речь ~228 слов/мин ≈ 3.8 слова/с ≈ 8 кадров на слово; смена картинки в среднем раз в 1.15 с;
медиана шота 2.15 с; статика не дольше ~3.6 с). В тесте Manim проверены строки «рот», «смех»,
«push-in», «встряска», «смена слова титра».

| Действие | Длительность, кадров @30 | Easing | Правило-источник и сверка |
|---|---|---|---|
| **Смена формы рта** (липфлап) | переход **0** (жёсткая подмена), держать **3–5** кадров (≈ слог; 228 сл/мин ≈ 5 слогов/с) | step, без твина | В эталоне рты сменяются, а не морфятся ([[style-bible]] §2). На паузах закрытый рот. В тесте подмена каждые 3 кадра читается |
| **Моргание** | закрытие 1–2 + закрыт 1 + открытие 1–2 = **3–5**; интервал 60–150 кадров (2–5 с), рандом | ease-in на закрытие, ease-out на открытие | micro-feedback 80–120 мс = 3–4 кадра; не синхронизировать у двух героев (ambient: разные периоды) |
| **Смена эмоции** (брови, глаза, рот) | упреждение-прищур **2–3** + переход **5–8** + overshoot-осадка **3–4** | ease-out-back, overshoot 5–10 % | Icon transition 150–250 мс; Playful overshoot ≤ 20 %, >25 % «сломано»; брови и усы через 2–3 кадра после рта (follow-through 50–150 мс) |
| **Смех-подпрыгивание** | цикл **8–12** кадров (в тесте 10); squash на контакте **2–4**, восстановление **4–8** | вверх ease-out, вниз ease-in (баллистика); squash — мгновенно | Disney: squash `[1.2,0.8]` максимум, для персонажа 1.08–1.15 по ширине с сохранением объёма; шляпа отстаёт на 2–4 кадра |
| **Поворот / наклон головы** | **6–10** (+ упреждение 3–4 при резком повороте) | ease-in-out (cubic) | Card/icon 200–350 мс; аксессуары доезжают на 2–5 кадров позже; наклон ±5–15° |
| **Жест рукой / «указать»** | замах **3–6** + действие **5–8** + осадка **4–6** | ease-out-back | Anticipation 10–20 % амплитуды; дуга, не прямая (Arcs, Playful 20+ px) |
| **Вход персонажа из-за края / выход** | вход **8–12**, выход **6–8** (65–75 % входа) | вход ease-out, выход ease-in | entrance-exit.md; путь > 1/3 кадра ломать ключом |
| **Медленный push-in на говорящего** | на весь шот: **45–150** (1.5–5 с), масштаб +8…+20 % | ease-in-out sine / `(0.4,0,0.2,1)` | Не дольше шота; внутри длинного 5–7-секундного диалога push-in и есть «смена картинки». В тесте 1.5 с, zoom 0.9→1.5 — уже агрессивно |
| **Whip / быстрый трекинг** | whip **4–8**, затем жёсткая склейка; трекинг — на всю длину полёта объекта | whip: ease-in-expo (разгон в склейку); трекинг: ease-in-out, в конце ease-out | Energetic 100–250 мс; motion blur обязателен (в Manim его нет). Сюда же «удар» камерой (импакт) — **9–12** |
| **Встряска камеры** (выстрел, взрыв) | **9–12** кадров, 2–3 колебания с затуханием, ±10–15 px | ease-in-out на каждом колебании, без overshoot | state-feedback.md, error shake 300–400 мс. В тесте 8 кадров ±0.08 юнита (~13 px) |
| **Смена слова титра** | переход **0** (жёсткая подмена на начале слова), держать **~8** кадров на слово (1–2 слова → 8–16) | step; поп-ин **не** делаем | [[style-bible]] §4: замена статична. Если решим добавить поп: 3–5 кадров, scale 0.85→1, ease-out-back ≤ 10 % (Playful quick 150 мс) — требует подтверждения Рауана |
| **Ритм склеек** | хук: **15–20** кадров на план (6 планов за 3.5 с); быстрые серии **18–45**; диалог **150–210** с движением камеры внутри; медиана **~65**; смена картинки в среднем раз в **~35** кадров; статика не дольше **~108** | склейка жёсткая; редкий световой «вспых» **4–6** кадров | Чисто замеры [[style-bible]] §3. Из motion-design: «быстро-быстро-МЕДЛЕННО» и 100–200 мс (3–6 кадров) покоя после развязки перед новым действием |
| **Эмбиент** (дыхание, пыль, свет ламп) | дыхание 60–120 кадров/цикл, масштаб ±1–2 %; пыль 10–30 px/с | sine, петля | ambient-continuous.md; амплитуда эмбиента ≤ 20 % основного движения |

**Перевод easing в код Manim** (`rate_functions.*`): ease-out-back → `ease_out_back`;
ease-in-out → `ease_in_out_cubic` / `ease_in_out_sine`; ease-out-expo → `ease_out_expo`;
`(0.4,0,0.2,1)` ≈ `smooth`; встряска — серия `linear`-шагов по 2 кадра с затуханием.

**Сигнатура канала** (по правилу motion-design «три константы»): easing — ease-out-back с
overshoot 8–12 % для персонажей и ease-in-out для камеры; палитра длительностей — **5 / 8 / 12**
кадров (быстро / стандарт / медленно); вход персонажа — «выпрыгнуть из-за края с осадкой».
