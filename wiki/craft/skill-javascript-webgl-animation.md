# Скиллы «Мульт на canvas» и «WebGL-сцены и частицы»

Разбор двух соседних пакетов iart-ai под задачу «ролик кодом в стиле [[style-bible]]».
Каталог всех кандидатов — [[anim-skills-catalog]], сборка конвейера — [[reproduction-pipeline]],
эталон — [[V001-how-mine-salting-worked]].

## Название

| Наше имя | Пакет | Скиллы | Что это |
|---|---|---|---|
| **Мульт на canvas** | `iart-ai/javascript-animation-skills` v0.4.1 | `javascript-animation`, `soundtrack` | Фильм в одном HTML: каждый кадр — чистая функция `draw(frame)` на 2D-canvas; рендер в MP4 через headless Chrome; музыка синтезом Web Audio; набор автопроверок |
| **WebGL-сцены и частицы** | `iart-ai/webgl-animation-skills` v0.1.0 | `threejs-animation`, `shader-glsl`, `particle-system` | Справочники-рецепты: three.js (сцена, камера, инстансинг, bloom/DOF, утечки GPU), GLSL (шум/fbm, SDF, переходы), частицы (бёрсты, дым, GPU `Points`) |

Первый пакет — **конвейер и контроль качества**, второй — **знания для 3D**. Своего
рендера в MP4 у второго нет (только скриншоты по `?t=N`), а первый явно отсылает 3D ко второму.
Вместе они закрывают «3D-мир + 2D-человечки» — это и проверено тестом ниже.

## Установка и запуск

- Клоны: `C:\dev\tools\anim-skills\javascript-animation-skills`, `C:\dev\tools\anim-skills\webgl-animation-skills`.
- Установлены как скиллы Claude Code: `javascript-animation`, `soundtrack` (в `~/.claude/skills/`).
  WebGL-пакет **не установлен** как скилл (в `~/.claude/skills/` есть посторонние `threejs` и `shader-dev`,
  это другие пакеты). Ставить: `npx skills add iart-ai/webgl-animation-skills`.
- Зависимости: Node 18+ (у нас 24.16), ffmpeg (у нас 8.1.2), Chrome. В **папке проекта** (не скилла):
  `npm i playwright-core` (у нас 1.65.1). Для 3D дополнительно `npm i three esbuild` (three 0.187).
- Скрипты запускаются из папки проекта по абсолютному пути до скилла — `playwright-core`
  подхватывается из текущей папки.

```bash
S=C:/dev/tools/anim-skills/javascript-animation-skills/skills
node $S/javascript-animation/scripts/render.mjs page.html out.mp4            # MP4 (+ .cues.json, + .wav если есть SCORE)
node $S/javascript-animation/scripts/render.mjs page.html sheet.jpg --sheet .5  # контактный лист, шаг 0.5 с
node $S/javascript-animation/scripts/render.mjs page.html shot --stills 0,62,2.5s  # отдельные кадры
node $S/javascript-animation/scripts/asset-audit.mjs page.html               # «ничего не грузится»
node $S/javascript-animation/scripts/layout-check.mjs page.html              # текст не налезает на текст/лицо
node $S/soundtrack/scripts/sync-check.mjs out.mp4 --cues-file out.cues.json  # склейки на долю, без «испуга»
```

## Как пользоваться

### javascript-animation (Мульт на canvas)
**Workflow скилла** (идёт без вопросов): бриф → свой look под тему → **данные в странице**:
`BPM`, `SECTIONS`, `SHOTS` (кадр, движение камеры, действие, на какую долю), `EVENTS`
(`[секунда, 'звук']`) → код от `templates/starter.html` → самопроверка → рендер → два прохода глазами
(`references/qc.md`: соответствие сториборду + «режиссёрский» проход по листу 2 к/с).

**Контракт страницы** (на нём держится всё):
- `window.draw(frame)` — чистая функция номера кадра. Никаких `Math.random`, `Date`, накопленной физики — только `rng(seed)`, `hash2()`.
- `window.FRAMES`, `window.FPS`; опционально `window.CUES` (секунды склеек/ударов), `window.SCORE = ac => {…}` (Web Audio), `window.LAYOUT` (боксы для layout-check).
- Страница грузится с `?render` — превью-цикл отключается.

**Ключевое API стартера**: «один мир — много камер» `withCamera({cx,cy,k}, fn)`; `claim(id,'text'|'keep',x,y,w,h)`
и `placeFree()` — подпись сама уходит от занятого; примитивы `ink/fill/hatch/shape/flatMass/glow/blush`,
`label()` с печатью по буквам, `drawLayer(fn, 'blur(4px)')`, изинги `ease/easeOut/back/prog`.
`references/character.md`: персонаж — одна функция с опциями `hero(cx,cy,r,{eyes,mouth,...})`,
сначала лист выражений отдельным кадром, якоря `mouthOf()/handOf()` для пропсов, порядок отрисовки сзади вперёд.
`references/storyboard.md`: таблица темпа (комедия 1–3 с на план), «каждый кадр живой», перенос объекта через склейку, направление движения.

### soundtrack
Партитура пишется кодом в `window.SCORE` (осцилляторы, шум, фильтры, свёрточный ревёрб из сида).
`render.mjs` рендерит её `OfflineAudioContext` → WAV → mux в MP4. Шаблоны `groove.js`
(биты, секции, 12 SFX, 4 кита, 6 гармоний) и `score.js` (музыкальная шкатулка, склейка = смена аккорда).
Правила: склейка на сильную долю, отмечать склейку гармонией, а не громкостью; слои вводить по 1–2 за такт;
пауза перед панчлайном. `sync-check.mjs`: берёт cues (или ищет склейки сам), находит онсеты звука,
валит при смещении > ±100 мс (OFF-BEAT) или скачке громкости > +6 дБ (STARTLE).

### threejs-animation
Сцена/камера/рендерер, `CatmullRomCurve3` для пролётов, `InstancedMesh` для шпал/камней,
`AnimationMixer` для GLTF (для рендера — `mixer.setTime(t)`, не `update(dt)`), bloom (`UnrealBloomPass`)
и DOF (`BokehPass`) через `EffectComposer`, подробный раздел про `dispose()` (нам почти не нужен — рендер одноразовый).
Контракт проверки — `?t=N` + скриншот `npx playwright screenshot` (`scripts/seek-shot.sh`).

### shader-glsl
Hash/value/simplex-шум, `fbm`, доменный варп, SDF-библиотека, косинус-палитры, переходы
(dissolve, displacement, glitch), подключение через `ShaderMaterial`. Для нас главное — процедурные материалы
камня/дерева и объёмный луч; переходы пригодятся на «вспых» при смене локации.

### particle-system
Интеграция сил, бёрст vs непрерывная эмиссия, рецепты конфетти/снег/**дым**, flow field/curl noise,
GPU `Points` с жизнью частицы в вершинном шейдере через `fract()`. Важно: рецепты на CPU **накапливают
состояние** (`step(dt)`) — для детерминированного рендера переписываем в замкнутую форму от `t` (см. тест).

## Что даёт для нашего стиля

Оценка: ●●● — закрывает почти полностью, ●● — даёт основу, надо дописать, ● — только идея, ○ — нет.

| Пункт стиля | Что даёт | Оценка |
|---|---|---|
| **3D-окружение** (тоннель, балки, рельсы, вагонетка) | three.js + процедурные материалы из `shader-glsl` (fbm-камень с трещинами и золотыми вкраплениями, дерево с волокнами через `onBeforeCompile`). Шахта из примитивов получилась за один заход. Городок, авто, деревья, водопад «уровня Pixar» из примитивов не сделать — нужны GLTF-модели (загрузчик описан, ассетов в пакете нет) | ●● |
| **Атмосфера**: тёплые лампы, лучи, пыль, туман, DOF | `PointLight` + `FogExp2`; god-ray конусом с аддитивным шейдером (френель + шум-полосы); 4000 пылинок в `Points`, ярче внутри луча; `UnrealBloomPass` + `BokehPass`. Выглядит близко к эталону | ●●● |
| **VFX**: пыль от удара, искры, взрыв, блики | бёрст пыли/облака/искр + каменные осколки; формулы из `particle-system`, переписанные в замкнутую форму от возраста частицы. Фитиль и взрыв — те же рецепты с другими параметрами | ●● |
| **2D-персонаж** в 3D (billboard) | `javascript-animation` даёт метод (персонаж = функция с опциями, лист выражений, якоря, «rounded forms»). В тесте человечек нарисован на 2D-canvas → `CanvasTexture` → плоскость, поворачивается к камере, получает туман; рты `flat/O/teeth`, глаза `dot/wide`, squash. Готовых персонажей нет — 4 архетипа пишем сами | ●● |
| **Камера** (push-in, трекинг объекта, низкий ракурс, тряска) | `withCamera` (2D) / любая функция `t → {pos, look, fov, focus}` (3D). Трекинг самородка, торможение, затухающая тряска, склейка на низкий ракурс — сделаны в тесте. POV через лупу — шейдер-линза из `shader-glsl` (не проверено) | ●●● |
| **Субтитры по слову** | Рисуются на 2D-слое поверх WebGL-кадра; `claim()` + `layout-check` гарантируют, что слово не легло на лицо. Тайминг — из таймкодов слов (whisper), в пакете этого нет | ●● |
| **Звук**: музыка + SFX, −14 LUFS | Синтез SFX (выстрел, свист, удар, осыпь) и подложки работает, `sync-check` полезен. Но: голоса нет совсем; «жанровая» музыка синтезом не получится (пакет сам это признаёт); `render.mjs` нормирует по пику (0.89), а не по LUFS — нужен `ffmpeg loudnorm` (тест: −15.5 → −14.7 LUFS одним проходом) | ● |
| **Рендер в MP4** | `render.mjs` работает с WebGL-страницей без правок, если соблюсти контракт `draw(frame)`. Детерминизм подтверждён (md5 кадра совпадает). Реальный GPU в headless | ●●● |
| **QA** | `layout-check` (текст vs лицо), `sync-check` (склейки vs звук), контактные листы, `qc.md`-чеклист, детерминизм. Нет: метрики «смен картинки в секунду», safe-зон Shorts, сравнения с эталоном — это у huashu/anidoodle | ●● |

## Результат теста (2026-11-14, Windows 11, RTX 5050 Laptop)

Папка: `C:\dev\tools\anim-tests\jsanim\`.

**(a) Стартер → MP4.** `starter.html` (1920×1080, 6 с, 180 кадров) → `starter.mp4` за **4.6 с** (~25 мс/кадр).
Контактный лист `starter-sheet.jpg`. Вариант с `groove.js` → `starter-score.mp4` + `.wav` за 6.6 с.
`layout-check`: CLEAN.

**(b) Шот «шахта», 720×1280, 30 fps, 4 с** — `mine\scene.js` → `mine\build.mjs` (esbuild собирает three.js +
addons в один IIFE и вклеивает в HTML, 597 КБ) → `mine\mine.html` → `mine\mine.mp4`.
Состав: тоннель-цилиндр с шумовой деформацией и fbm-шейдером камня, 6 рам из балок с шейдером дерева,
рельсы + 76 шпал инстансом, вагонетка, 6 ламп с bloom, конус-луч с полосами, пятно света на полу,
4000 пылинок, самородок со свечением и шлейфом, рейкаст точки попадания в реальную стену,
бёрст в 2.0 с (900 частиц пыли + 70 «облаков» + 160 искр + 26 осколков), трекинг камеры → торможение и тряска →
склейка в 2.8 с на низкий ракурс с наездом, DOF по самородку/стене, billboard-напарник (жёлтая шапка, бирюзовая кофта,
рот «O» → «оскал»), пословные субтитры, синтез-звук (выстрел, свист, удар, осыпь, дрон, тики 120 bpm).
- Контактные листы: `mine\mine-contact.jpg` (ffmpeg `fps=3,tile=6x2`), `mine\mine-sheet.jpg` (render.mjs `--sheet .5`), кадры `mine\full-pair.jpg`.
- **Скорость**: полный рендер 120 кадров с аудио — **9.8 с** (~80 мс/кадр с запуском Chrome и компиляцией шейдеров ~2 с).
  Бенч `mine\bench.mjs`: `draw()` 1.6 мс, чтение кадра `toDataURL` JPEG ~14 мс → установившийся темп ~16–20 мс/кадр в браузере.
  Оценка для 60-секундного ролика (1800 кадров): **~1.5–2.5 мин**.
- GPU в headless: `ANGLE (NVIDIA GeForce RTX 5050, D3D11)` — не SwiftShader, т. е. быстро.
- Детерминизм: кадр 75 до и после рендера другого кадра — md5 совпадает.

**(c) sync-check.** `mine.cues.json` = `[2, 2.8]`: удар в 2.0 — STARTLE +6.4 дБ (намеренный «стингер»,
допустимо по правилам скилла), склейка 2.8 — ok (−80 мс). Без cues скрипт сам нашёл «склейку» в 1.77 с —
это быстрый пролёт камеры, ложное срабатывание (пакет об этом предупреждает). На стартере с `groove.js`:
удар коробки 2.3 с — STARTLE +8.2 дБ, остальное ok.

**Проблемы Windows и их обход**
1. `asset-audit.mjs` всегда «NOT zero-asset»: сравнивает `'file://' + resolve(file)` (`file://C:\...`) с адресом запроса
   (`file:///C:/...`) и считает саму страницу внешней загрузкой. Обход: копия с `pathToFileURL(resolve(file)).href`
   (`jsanim\asset-audit.patched.mjs`) — на стартере CLEAN. Оригинал не трогали.
2. `asset-audit` на любой странице с вклеенной библиотекой (three.js) даёт ложные «CSS url(...)» — регулярка
   регистронезависима и ловит JS `new URL(`. Для 3D-страниц аудит информативен только глазами.
3. `probe-mp4.sh` (webgl-пакет) падает с ffmpeg 8.x: `ffprobe -of csv=p=0` теперь ставит хвостовую запятую
   (`720,x1280,`). Не Windows-баг, а версия ffprobe; лечится `-of default=nw=1:nk=1`.
4. `render.mjs`/`layout-check`/`sync-check`/`contact-sheet.sh` работают в Git Bash и PowerShell без правок.
5. ES-модули и CDN по `file://` — плохо (CORS, сеть, ломает «нулевые ассеты») → three.js собираем esbuild'ом в один скрипт.
6. Подвох `BokehPass`: его depth-проход рисует и прозрачные объекты (луч, пыль, свечения) как твёрдые стены —
   оборачиваем `bokeh.render`, прячем их на время прохода.
7. GLSL: подстановка отрицательного числа в шаблон дала `--0.05` → ошибка компиляции; ловится только по `pageerror`
   (чёрный/пустой кадр). Бенч-скрипт выводит ошибки страницы.

## Ограничения

- **Нет голоса** и пословного тайминга озвучки — берём TTS + whisper со стороны (см. [[reproduction-pipeline]]).
- **Нет ассетов**: городок, машина, деревья, водопад, лица уровня эталона из примитивов не собрать; философия
  пакета «ноль ассетов» конфликтует с GLTF-моделями — для нас правило снимаем, `asset-audit` не используем как гейт.
- **WebGL-пакет — справочник, не инструмент**: нет рендера в MP4, его контракт `?t=N` + `mixer.update(dt)`/`clock.getDelta()`
  не детерминирован для покадрового рендера — переводим всё на `draw(frame)` из javascript-animation.
- Рецепты частиц на CPU копят состояние — для seek-рендера переписывать в замкнутую форму.
- `render.mjs` гонит JPEG 0.93 через base64 → потеря качества на градиентах пыли/тумана (лучше PNG или
  `canvas.toBlob` + raw), громкость — по пику, не LUFS.
- 9:16 — узкий кадр: два объекта (стена + напарник) не помещаются без широкого объектива; в тесте напарник
  частично обрезан правым краем в конце шота — композиция требует итераций по контактным листам.
- Персонажи «как у Рауана» (4 архетипа, набор ртов под речь) — писать с нуля; пакет даёт только метод.
- Пакет тестировался авторами только на Claude Opus 5.5; качество рисунка зависит от модели.

## Вердикт: роль в стеке

**Брать оба, в связке.** `javascript-animation` — **скелет конвейера**: контракт `draw(frame)`, `render.mjs`
(работает и для WebGL), CUES/EVENTS как единый источник правды для картинки и звука, `layout-check` для
субтитров, `sync-check` для склеек, `qc.md` и контактные листы для самопроверки. `webgl-animation-skills` —
**учебник для 3D-слоя**: процедурные материалы, луч-конус, пыль и бёрсты, bloom/DOF — всё это в тесте дало
картинку, уже близкую к эталону по атмосфере, при рендере ~10 с на 4 с видео.

Не закрывают: голос, модели сложных локаций, готовых персонажей и −14 LUFS — это другие звенья
([[reproduction-pipeline]]). Ставить `webgl-animation-skills` как скилл стоит; `asset-audit` в нашем
стеке — не гейт; `sync-check` использовать с явными `--cues-file`, ударные SFX помечать как стингеры.
